# Design Context

## Users

This package serves authenticated Laravel application operators who need to deploy one preconfigured Laravel Forge site without receiving server credentials or unrestricted Forge access. Users are technically capable but should be able to understand the current state and safely trigger a deployment at a glance.

## Brand Personality

Quiet, trustworthy, precise. The interface should feel native beside a well-built Laravel administration area while remaining visually independent of any host application's CSS framework. It should communicate operational seriousness without looking intimidating or sterile.

## Aesthetic Direction

Use a restrained, editorial developer-tool aesthetic with warm neutral surfaces, deep ink text, a focused red-orange action color inspired by Laravel, and clear semantic state colors. Favor strong type hierarchy, generous whitespace, crisp borders, and compact operational data. Support automatic light and dark color schemes, right-to-left locales, keyboard navigation, reduced motion, and narrow screens. Avoid gradients, glass effects, excessive cards, novelty decoration, and external font or icon dependencies.

## Design Principles

1. Make risk visible before action: identify the exact target and branch beside the deploy control.
2. Fail closed and explain why: unavailable or incomplete configuration must disable deployment with a useful message.
3. Prefer shared operational truth: current status, Forge history, output, and local actor attribution belong on one screen.
4. Keep credentials absent: never render tokens, server credentials, or deployment hook secrets.
5. Work anywhere Laravel works: no dependency on Bootstrap, Tailwind, Alpine, or a host layout.
